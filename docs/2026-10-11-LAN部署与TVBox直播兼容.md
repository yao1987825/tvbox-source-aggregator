# 局域网部署 & TVBox 直播兼容 — 修复与部署记录

本文档对应一次完整的局域网(内网)环境实战：从部署、源选型、到 TVBox 客户端兼容的全链路。涉及到多次代码修改、镜像重建、配置调优等。读者可按本文档复现完整流程。

环境:**192.168.6.0/24 LAN,Docker 部署,SOCKS5 代理 192.168.6.1:1070(未启用)。**

---

## 一、问题背景

服务部署在一台内网服务器上,TVBox 客户端在内网访问,具体网络环境有两个特征:

| 网络位置 | 状态 |
|---|---|
| 服务器出网(常规 GitHub/镜像) | `raw.githubusercontent.com`、`gh-proxy.com`、`mirror.ghproxy.com` **被墙**(墙内出境拦截) |
| 服务器出网(jsDelivr CDN) | ✅ 正常(`cdn.jsdelivr.net` 走 Cloudflare 节点) |
| 内网 LAN(192.168.6.x) | 全通 |

聚合器一开始只有一条 `gh-proxy.com/...raw.githubusercontent.com/...` 源,所以一刷新就 timeout → 失败,聚合结果就是 0 个站点、0 个直播。

**TVBox 直播只能看到 1 个 "default" 分组**:服务器侧实际上有完整数据(Native 格式 26 组 / 2555 频道),但客户端 fork 不识别 Native inline 也不跟 URL,只能从单独 m3u 源才能拉到。

## 二、修复措施

### 1. 默认 fetch 超时放宽:`5s` → `10s`

`src/core/config.ts`:

```ts
// before
export const DEFAULT_FETCH_TIMEOUT_MS = 5000;
// after
export const DEFAULT_FETCH_TIMEOUT_MS = 10000; // 10s,适配代理/不稳定链路
```

`.env.example` 同步注释:**"5000→10000:代理链路建议 10000-15000"**。

### 2. 源 URL 切换:gh-proxy → jsDelivr

LAN 网络出不去 GitHub raw,只能走 jsDelivr。把默认源从

```
https://gh-proxy.com/https://raw.githubusercontent.com/qist/tvbox/master/fty.json
```

改成

```
https://cdn.jsdelivr.net/gh/qist/tvbox@master/fty.json
```

规则:任何 `https://raw.githubusercontent.com/<u>/<r>/<path>` URL 都可以等价替换成:

```
https://cdn.jsdelivr.net/gh/<u>/<r>@<branch>/<path>
```

### 3. SOCKS 代理尝试 → 放弃(本次不接入)

环境上有 `192.168.6.1:1070` 的 SOCKS5 代理,试过把 `socks-proxy-agent@8 + undici@6` 接到 `fetcher.ts`,但**undici v6 要求 dispatcher 有 `.dispatch()` 方法,socks-proxy-agent@8 还是 `http.Agent`,完全不兼容**。三个修复手段都用尽了(dispatcher pool、import 路径、运行时 fallback),最终还是放弃。日志卡在:

```
TypeError: agent.dispatch is not a function
    at undici/lib/web/fetch/index.js
```

打算未来手写一个基于 `socks@2.x` 包的 undici Dispatcher(30-50 行代码),**当前 PR 未集成**。如果你暂时需要走代理,临时方案:在 `docker-compose.yml` 加一层 `gost` HTTP→SOCKS 桥,然后用 `HTTP_PROXY=http://localhost:1080` 这种 env,但走容器内 jsDelivr CDN 通常就直接够了。

### 4. 直播组名清理 + 双 URL 格式

修了两个老 TVBox fork 的解析 bug:

| 老 fork 的 bug | 触发 | 修复 |
|---|---|---|
| 「源名」前缀 + emoji 组名无法解析,回落到 "default" | 组名带 📺📡🪁☘️ 时 | `stripEmoji()` 去掉 emoji,「」 改用空格分隔 |
| 期望 `urls: "url1#url2"`(字符串)而不是数组 | 同时输出 `urls: [...]` 和 `url: "..."` 双格式 |

`src/core/live-merger.ts` 新增 `stripEmoji()`,`separatedMergeLives` / `mergeLivesToNative` / `fetchAndParseLiveUrls` 三处输出都加 `url: urls.join('#')` 兜底字段。

### 5. 新增 `/live.m3u` 端点

老 TVBox fork 100% 都能识别标准 m3u playlist。新加的端点返回:

```
GET http://192.168.6.135:5678/live.m3u
Content-Type: audio/x-mpegurl; charset=utf-8

#EXTM3U
#EXTINF:-1 group-title="综合直播 - 央视频道",CCTV1
http://173.208.212.130:8181/720p/cctv1.m3u8
#EXTINF:-1 group-title="综合直播 - 卫视频道",安徽卫视
http://173.208.212.130:8181/720p/ahws.m3u8
...
```

数据源是 `KV_CHANNEL_MERGED_TREE`(Step 6.5 写入的合并树),不依赖 `KV_MERGED_CONFIG.lives` —— 因为后者已被改成 FongMi URL 指针,会触发 `isNativeLiveGroups()` 返回 false。**`/live.m3u` 是最通用的直播入口,TVBox fork 一律通吃**。

### 6. 主配置 hybrid lives

`src/aggregator.ts` Step 6.5:`merged.lives` 改为 hybrid:

```js
merged.lives = [
  { name: '聚合直播源', type: 0, url: '{{BASE_URL}}/live.m3u' },  // URL 指针
  ...mergeResult.groups,                                       // Native inline 数组
];
```

| TVBox fork 行为 | 走哪路 |
|---|---|
| 支持 `lives[0].url` 下载 | 自动拉 `/live.m3u`,渲染 m3u 全部频道 |
| 支持 Native inline `lives[1..].group + channels` | 直接渲染 4 个内联分组 |
| 都不支持(纯本地源模式) | 用户在 TVBox 中加 `/live.m3u` 作为独立直播源 |

`{{BASE_URL}}` 在服务端渲染时替换为 `http://192.168.6.135:5678`(从 `BASE_URL` env 推断)。

---

## 三、4 个端点总结

| 端点 | Content-Type | 格式 | 大小 | 用途 |
|---|---|---|---|---|
| `/` | application/json | TVBox 主配置 | ~28 KB | **TVBox 主填这条**,含 sites + parses + live (hybrid) |
| `/live.m3u` | audio/x-mpegurl | 标准 M3U 播放列表 | ~5 KB | **兼容最广**,所有 fork 都识别;主 URL 不生效时独立加 |
| `/live.json` | application/json | 仅 lives 字段的 JSON | ~357 KB | 仅做内部用 |
| `/live-config` | text/plain | DIYP TXT (`#genre#`) | ~161 KB | 老 P2P 系 fork |

## 四、端到端部署步骤(LAN 实例)

### 0. 服务器初始化(一次性)

SSH 进内网服务器:

```bash
ssh yao@192.168.6.135
# 这台机器免密登录,Docker 已装
```

### 1. 克隆/同步仓库

```bash
cd ~
git clone https://gitee.com/tengxiaobao/tvbox-source-aggregator.git tvbox-source-aggregator
cd tvbox-source-aggregator
# 如果已 clone,改完代码就 git pull,或者从开发机 scp 同步
```

### 2. 配 `.env`

```bash
cp .env.example .env
# 关键值:
cat > .env <<'EOF'
ADMIN_TOKEN=yaojiwei               # 管理后台密码(必填)
PORT=5678                          # 端口
BASE_URL=http://192.168.6.135:5678  # 局域网访问地址,Docker 必填(供 JAR/图片代理)
CRON_SCHEDULE=0 5 * * *             # UTC 5:00 = 北京 13:00,每天刷新
REFRESH_TOKEN=                      # 留空 = 用 ADMIN_TOKEN
SPEED_TIMEOUT_MS=5000
SITE_TIMEOUT_MS=3000
FETCH_TIMEOUT_MS=10000              # 默认 10s,适配代理/不稳定链路
DATA_DIR=
EOF
```

### 3. 启动

```bash
docker compose up -d --build    # 首次需要 build,后续只用 up -d
docker compose logs -f          # 看启动日志
```

确认日志里看到:

```
[storage] SQLite initialized: /app/data/tvbox.db
[cron] Scheduled: 0 5 * * *
[channel-probe-cron] Scheduled: 0 */12 * * * (runs when enabled)
```

### 4. 添加源(jsDelivr,可访问 GitHub 用 CNAME 即可)

去 `http://192.168.6.135:5678/admin`(token `yaojiwei`),源管理加:

| 名称 | URL |
|---|---|
| `qist-fty` | `https://cdn.jsdelivr.net/gh/qist/tvbox@master/fty.json` |
| (可选)其它 jsDelivr 镜像 | 自己替换 `<user>/<repo>@<branch>/<path>` |

记得点 **Refresh** 手动触发一次聚合。

### 5. 验证

```bash
# 主配置大小,live 字段验证(hybrid)
curl -s http://192.168.6.135:5678/ | node -e "
let d='';process.stdin.on('data',c=>d+=c).on('end',()=>{
  const j=JSON.parse(d);
  console.log('sites:', j.sites?.length);
  console.log('parses:', j.parses?.length);
  console.log('lives.length:', j.lives?.length);
  console.log('lives[0]:', JSON.stringify(j.lives[0]));
  console.log('lives[1] keys:', Object.keys(j.lives[1]||{}));
});
"

# M3U 端点(直播源)
curl -s http://192.168.6.135:5678/live.m3u | head -10
curl -s -o /tmp/m3u http://192.168.6.135:5678/live.m3u
grep -c "^#EXTINF" /tmp/m3u    # 应大于 0
```

期望日志(看 `docker compose logs`):

```
[aggregation] Step 2: Fetching configs...
[fetcher] Direct source fetch will use proxy: (空,直连)
[fetcher] Fetched N configs from N top-level sources
[live-merger] Separated done: K/K sources, G groups, C channels
[aggregation] done elapsed=Xs sites=... parses=... lives=G+1
```

### 6. 配 TVBox

**TVBox 主配置地址 = `http://192.168.6.135:5678/`**

如果你的 TVBox fork 在主配置里看不到直播,把 `/live.m3u` 单独加到"自定义直播源":

```
直播源 = http://192.168.6.135:5678/live.m3u
```

## 五、常见故障定位

### 聚合一直 0 源

```bash
docker compose logs | grep -E "fetcher|aggregation" | tail -20
# 看每条源卡在哪。如果是 socket/ETIMEDOUT → 那条 URL 网络不通,换 jsDelivr 或换源
```

### 直播只剩 "default"

1. 浏览器访问 `http://192.168.6.135:5678/live.m3u` 验证能不能拉到 m3u 文件
2. 浏览器访问 `http://192.168.6.135:5678/` 验证 lives 字段是不是 hybrid(应该带 1 个 URL 指针 + N 个 Native group)
3. TVBox 客户端版本 / fork 名字确认一下,有些老 fork 真的只支持 m3u 单独源

### 修改代码后怎么重建

```bash
# 在开发机上改完 → git push 或 scp 到服务器
ssh yao@192.168.6.135 "cd ~/tvbox-source-aggregator && git pull && docker compose up -d --build"
# 或简单重建(无 git):
scp -r src/ package.json scripts/ yao@192.168.6.135:~/tvbox-source-aggregator/
ssh yao@192.168.6.135 "cd ~/tvbox-source-aggregator && docker compose up -d --build"
```

### 强制重新聚合

```bash
curl -X POST -H "Authorization: Bearer yajiwei" http://192.168.6.135:5678/refresh
# 或者直接调 admin 后台的 Refresh 按钮
```

### 看过往聚合日志

`http://192.168.6.135:5678/admin` → 「聚合日志」,看成功/失败、最近一次聚合来源数、新增/移除站点数等。
